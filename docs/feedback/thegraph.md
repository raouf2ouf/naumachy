# The Graph - feedback

Dated developer-experience entries from building Aquascan (subgraphs per chain, a pools subgraph, an arena subgraph) and the gym (a local graph-node over an anvil fork of Base).

## For the tracks: the composition and what the shared schema bought us

**The products composed.** Six Aqua subgraphs published on The Graph Network, one per chain (`subgraphs/aqua`, ids in its README); a Substreams package for Robinhood Chain, which The Graph serves only through Firehose (`substreams/aqua`); a pools subgraph and an arena subgraph on Base over our own registry (`6gaE5WQj7UQKtnhd85N3cLsKcSohdtG37CLmmP8UyiGp`); The Graph's Subgraph MCP as the gladiators' query layer on the network (`agents/src/tools.ts`, `GLADIATOR_GRAPH=mcp`); and, on top of all of it, the Aquascan MCP (`mcp/`), so the same questions reach Claude, Cursor and anyone else at `naumachy.xyz/mcp`.

**Load-bearing.** Aquascan has no chain lane other than The Graph: the enrichment reads the gateway and replays the Substreams events into the same tables; prices come from DefiLlama and the venue's own tape, never from an RPC scan. The gladiators' briefing (generations, entries, attested scores, rivals' programs), their tools while they write, and the lanista's scoring all read Graph data. Stop the gateway and the arena stops.

**What became easier because one schema served every chain.** The Aqua subgraph is one manifest deployed seven ways (six network deployments and the gym's local graph-node over a fork), and the Substreams replay writes into the same tables with the same ids. Everything downstream is written once: the rollup that computes edges, markouts and P&L, the API, the web, the minds' tools and the MCP never ask which lane a chain came from. Adding Robinhood Chain, a third of the venue's volume, changed no consumer. The arena subgraph joins the Aqua one on the strategy hash (`Entry.strategyHash` is the tail of Aquascan's strategy id), so "what did the champion's program do on the venue" is one lookup. And the gym is the same code as the network: a mind developed against a local graph-node runs unchanged against the gateway, the GraphQL identical, only the transport swapped.

**Where it was hard**, in the entries below: a chain the network reaches only through Substreams, the Substreams JavaScript client, a stalled ingestor on a fork, the MCP that cannot see a local node, and the network id that lives only in the publish dialog.

**Pool selection.** Composable products: the composition above, six subgraphs plus one Substreams package plus two consumers over one schema. AI use case, from scratch: the gladiators' minds reason on Graph data to write programs, and the Aquascan MCP turns the data into questions.

## Entries (dated)

- 2026-09-08 Robinhood Chain carries a third of Aqua's volume and is in the networks registry with Firehose and Substreams endpoints, but its subgraph service list is empty, so Studio refuses a subgraph for it. A team with a working subgraph on six chains has to write a second reader (we chose a Substreams package and a replay lane) or run graph-node itself. A note on the Studio network picker saying "Substreams only" with a link would have saved an evening of guessing.
- 2026-09-08 `substreams init` is a remote code generator driven by an interactive terminal UI; there is no flag to feed it the answers, so it cannot run in a script or from an agent. The templates it renders are readable on GitHub and hand-writing the package from them took less time than fighting the UI.
- 2026-09-08 The JavaScript client splits across `@substreams/core`, `@substreams/node` and `@substreams/manifest`. The node transport sends a token as `X-Api-Key`, which a Graph Market JWT rejects with a message about API keys; the manifest package needs `effect` peers it does not declare as dependencies. A single documented path for "Graph Market token, Node.js, read an .spkg" would help.
- 2026-09-09 A gRPC stream the client cancels keeps counting against the free tier's two concurrent sessions for minutes after the cancel. A consumer that reads in time slices, the natural shape for a poller, trips `resource_exhausted` on its own previous slice. Releasing the slot on cancel, or a higher limit for short-lived streams, would make polling consumers viable on the free tier without a workaround.
- 2026-09-08 `substreams run` without `--production-mode` processed 400,000 blocks sequentially and printed nothing for ten minutes. The default fits debugging a module on a hundred blocks; a hint when the range is large would help.

- 2026-09-08 A local graph-node over a fresh anvil fork of Base stalled for good at the fork block: the block ingestor downloads the head's 50 ancestors at start (`ETHEREUM_ANCESTOR_COUNT`), and a pre-fork Base block served through anvil from the upstream RPC failed `eth_getBlockReceipts` parsing (`missing field blockNumber`) on every retry, so no subgraph advanced and `indexingStatuses` showed a null `chainHeadBlock` with `health: healthy`. A restart once the fork had mined 50 blocks fixed it. Two asks: surface the ingestor's stuck state in `indexingStatuses` (a healthy subgraph that cannot move is not healthy), and let `ETHEREUM_ANCESTOR_COUNT` be documented next to `GRAPH_ETHEREUM_REORG_THRESHOLD` for fork-based development.
- 2026-09-08 The Subgraph MCP (`subgraphs.mcp.thegraph.com`) cannot reach a local graph-node, which is the right boundary, but it means an agent developed against a fork uses a different tool than the one it uses on the network. We kept the GraphQL identical and swapped the transport (`GLADIATOR_GRAPH=local|mcp`); a documented way to point the MCP at a self-hosted node for development would remove the split.
- 2026-09-12 `graph deploy <slug>` answers "Subgraph not found" until the slug has been created by hand in Studio; the CLI cannot create it. A `--create` flag, or a message that says "create it at thegraph.com/studio first", would save the round trip.
- 2026-09-12 After publishing, the network id appeared nowhere the CLI could read; we recovered it from the network registry subgraph (`subgraphs(where: {metadata_: {displayName_contains_nocase}})`, id base58) and wrote it into our README by hand. The gateway served the new arena subgraph within a minute of the Arbitrum transaction, synced from the registry's deployment block, no signal needed. Printing the network id at the end of `graph publish`, or exposing it on the Studio page as text, would close the loop.
- 2026-09-12 Wrapping the read-only API in an MCP server took one afternoon because every number already carried its source; the tools collapse provenance objects to values and list the sources once. The pattern would suit a Graph-side "questions over a subgraph" layer: the schema is there, the gateway is there, what is missing is the sentence that names the question.
