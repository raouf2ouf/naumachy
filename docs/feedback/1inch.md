# 1inch Aqua / SwapVM - feedback

Not required by the track, but every placing Aqua project shipped one. Filled as we go: SDK ergonomics, docs gaps, dialect/version confusion, anything the validator loop caught that looks like a protocol issue (those go to HackenProof first, here second).

## For the track: what to look at

- **A custom Aqua app.** `contracts/src/NaumachyRouter.sol` is the full SwapVM v1.0.2 router redeployed with three instructions appended at `0x2e`, `0x2f`, `0x30` (`contracts/src/instructions/`): `ToxicityFee`, a maker fee that widens with recent one-way flow and decays over a window; `RiskCap`, no fill may move more than a share of either balance, read from the ledger at entry so a virtual curve cannot lift it; `OracleAnchor`, the curve re-centred on a pool oracle before the swap, up to three pairs in one instruction so one inventory quotes three markets. Deployed and verified on Base: [0x7f417e540899a054bbb287de1c04a13d7d2d98c7](https://basescan.org/address/0x7f417e540899a054bbb287de1c04a13d7d2d98c7). Strategies ship to the canonical Aqua registry with this router as their app.
- **Official contracts.** `Aqua` v1.0.0 and `swap-vm` v1.0.2 as unmodified submodules; every upstream instruction keeps its byte; the router is a redeployment, as the track allows.
- **On-chain execution.** Foundry on a fork of Base against the canonical registry with real WETH, USDC and cbBTC (`contracts/test/NaumachyRouter.t.sol`, `NaumachyPairs.t.sol`: quotes track the pool, swaps move tokens, quote equals swap, the loop through three pairs never pays the taker, the fee widens and forgets, the cap holds). Live on Base since 2026-09-12: four AI-authored programs with real inventory, filled through our `Taker` contracts, for example [0xa5a5e00f…](https://basescan.org/tx/0xa5a5e00ff5c80a7fa4fb26b9adf2c3f1d87b04749af1e1a721bcfe9ca67ab105).
- **A sophisticated position.** The arena's dialect composes a pass gate (SwapVM's own `OnlyTakerTokenBalanceNonZero` on our `ArenaPass`), fees by the token the taker pays (`JumpIfTokenIn` branches), the toxicity fee, the anchor and the swap; the compiler (`arena/src/program.ts`) puts `RiskCap` first and a language model writes the rest. Aquascan reads every program on the venue back into a card, ours and the wild's (`aquascan/api/src/swapvm.ts`).
- **Findings for the protocol** go to HackenProof first. None of the entries below is a vulnerability; they are documentation and ergonomics.
- **License.** Our code is MIT; the submodules keep Degensoft's Aqua-Source-1.1 and SwapVM-1.1.

## Entries (dated)

- 2026-09-08 The Aqua README says the registry has no callbacks, and that is true of `Aqua.sol`; but SwapVM's settlement calls `IMakerHooks` (pre and post transfer in and out, `MakerTraits` bits 252 to 245, a target contract or the maker itself) in Aqua mode as well, and `test/MakerHooks.t.sol` only exercises signature mode. We read the Aqua side first and wrote "no maker hook" into our own docs, then found the hooks by reading `SwapVM.sol` and proved them on a fork: a maker holding no WETH filled a buy through a pre-transfer-out hook that pulled inventory from a vault. One paragraph in the SwapVM README under "For Makers" ("hooks run in both settlement modes; in Aqua mode the maker's wallet must hold the tokens by the time `pull` runs, which a pre-transfer-out hook can arrange") and one Aqua-mode case in the hooks test would have saved a day of wrong design.
- 2026-09-08 Instruction arguments carry one byte of length, so 255 bytes is the ceiling for any instruction's data. Our multi-pair anchor needs 63 bytes per pair (oracle, base, quote, three decimals), so three pairs fit and four do not. A note in the README's bytecode section ("args_len is one byte") would make this a design input rather than a compile-time surprise; a two-byte length for a reserved opcode range would lift it.
- 2026-09-08 Jumps around middleware. A fee instruction runs the rest of the program nested inside itself and leaves the shared program counter at the end of the program, so a branch of fee instructions selected by `JumpIfTokenIn` must end with a `Jump` to the common tail, or the other branch executes too. Nothing in `docs/PROGRAMS.md` shows a branch that contains middleware; the "best route selector" example branches over swap instructions only. Worth an example, since fee-by-direction (skew) is the first thing a market maker wants and the layout is not obvious.
- 2026-09-08 `Aqua.safeBalances` reverts with `SafeBalancesForTokenNotInActiveStrategy` for a pair the strategy never shipped, before any instruction runs. Good behaviour, but it means an instruction's own pair guard can only fire for shipped pairs; a line in the Aqua README's "For Traders" would tell integrators which error to expect.
- 2026-09-08 What worked without friction: shipping a three-token strategy (one ledger, three pairs, every pair quoted from the same balances), the taker-balance gate (`OnlyTakerTokenBalanceNonZero`) as an access list with our own pass token, and `quote()` as the validator for programs written by a language model, including a round trip through three pairs on a private fork before anything ships.
- 2026-09-12 On Base, 1inch's resolvers route only to the canonical routers, so a custom app at another address never sees third-party flow; every fill on our programs comes from our own engine. Expected, and stated in our README, but a way for a custom router to opt into resolver routing (an allowlist, or a registry of apps with their instruction tables) would let a modified router be tested against real takers, which is the truest fitness function there is.
- 2026-09-12 Fee arguments are on a 1e9 base (one basis point is 100,000) while every dashboard, including 1inch's, speaks in bps. Our dialect converts; a note beside each fee instruction in `PROGRAMS.md` giving the base would save a first program from charging 0.00001 bps.
