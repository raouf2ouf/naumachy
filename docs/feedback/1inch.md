# 1inch Aqua / SwapVM - feedback

Not required by the track, but every placing Aqua project shipped one. Filled as we go: SDK ergonomics, docs gaps, dialect/version confusion, anything the validator loop caught that looks like a protocol issue (those go to HackenProof first, here second).

## Entries (dated)

- 2026-09-08 The Aqua README says the registry has no callbacks, and that is true of `Aqua.sol`; but SwapVM's settlement calls `IMakerHooks` (pre and post transfer in and out, `MakerTraits` bits 252 to 245, a target contract or the maker itself) in Aqua mode as well, and `test/MakerHooks.t.sol` only exercises signature mode. We read the Aqua side first and wrote "no maker hook" into our own docs, then found the hooks by reading `SwapVM.sol` and proved them on a fork: a maker holding no WETH filled a buy through a pre-transfer-out hook that pulled inventory from a vault. One paragraph in the SwapVM README under "For Makers" ("hooks run in both settlement modes; in Aqua mode the maker's wallet must hold the tokens by the time `pull` runs, which a pre-transfer-out hook can arrange") and one Aqua-mode case in the hooks test would have saved a day of wrong design.
- 2026-09-08 Instruction arguments carry one byte of length, so 255 bytes is the ceiling for any instruction's data. Our multi-pair anchor needs 63 bytes per pair (oracle, base, quote, three decimals), so three pairs fit and four do not. A note in the README's bytecode section ("args_len is one byte") would make this a design input rather than a compile-time surprise; a two-byte length for a reserved opcode range would lift it.
- 2026-09-08 Jumps around middleware. A fee instruction runs the rest of the program nested inside itself and leaves the shared program counter at the end of the program, so a branch of fee instructions selected by `JumpIfTokenIn` must end with a `Jump` to the common tail, or the other branch executes too. Nothing in `docs/PROGRAMS.md` shows a branch that contains middleware; the "best route selector" example branches over swap instructions only. Worth an example, since fee-by-direction (skew) is the first thing a market maker wants and the layout is not obvious.
- 2026-09-08 `Aqua.safeBalances` reverts with `SafeBalancesForTokenNotInActiveStrategy` for a pair the strategy never shipped, before any instruction runs. Good behaviour, but it means an instruction's own pair guard can only fire for shipped pairs; a line in the Aqua README's "For Traders" would tell integrators which error to expect.
- 2026-09-08 What worked without friction: shipping a three-token strategy (one ledger, three pairs, every pair quoted from the same balances), the taker-balance gate (`OnlyTakerTokenBalanceNonZero`) as an access list with our own pass token, and `quote()` as the validator for programs written by a language model, including a round trip through three pairs on a private fork before anything ships.
